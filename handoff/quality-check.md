## 1. まず守ること（`CLAUDE.md` と同じ）
- **すべて GAS でつなぐ。** 予約・アンケート・ありがとうシステム・品質チェックシートは、ひとつのサービス（SaaS）として作る。品質チェックシートだけ別の仕組みにしない。
- **お客さまは「顧客キー」で書く。** `gas/survey/Hub.gs` の `customerKey()`（メールから作る `C-`＋16文字。どのGASで計算しても同じ値）と `upsertCustomer()`（顧客ハブの台帳に載せる）を使う。
- **予約表は読むだけ。** 書きかえない。
- **このリポジトリは公開の GitHub Pages。** スプレッドシートのID・トークン・個人情報は、コードにも文書にも書かない。GAS のスクリプトプロパティに入れる。ファイルはドライブで名前を検索して開く。
- **説明は日本語で、例え話を添える。詳しい話に入る前に、まず確認の質問をする**（三浦さんの希望）。
- 設計・手順・決めたことは、**橋口さん・松本さん・ありがとうグループのメンバー**にも共有する。共有用の文書は Claude Docs で作ってリンクを渡す。
- 作業は `main` に直接しない。ブランチを切って push する（`main` が公開サイト）。

## 4. 進め方のおすすめ
1. 「品質回答」と「予約台帳」タブを、**見出しだけ**読む（Google Drive の `read_file_content`。お客さまの個人情報は書き出さない）。会社GASのコードがどこにあるかも三浦さんに聞く。
2. 3の質問の答えから、項目と流れを Claude Docs の共有文書にまとめて、三浦さんの OK をもらう。
3. 記録は `jobId` を軸にし、`jobId → 予約台帳の email → customerKey()` で顧客キーも書く。こうすると、アンケートや予約と同じお客さまとしてつながる。
4. 画面はスマホが先。`survey.html` と `css/site.css` の部品（`.card` `.opt` `.btn`、大きな文字・くっきり表示）を使う。
5. GAS は `gas/survey/test/mock-run.js` と同じやり方で、にせのスプレッドシートを使ってテストしてから渡す。
6. 三浦さんが操作するのは「Apps Script に貼る・デプロイする・権限を許可する」ところだけになるようにする（GAS は1ファイルにまとめ、秘密でない設定には既定値を入れる）。
